# Спецификация: отправка email-уведомлений

Вынесено из `ARCHITECTURE.md` §2.5 в отдельный файл — тема достаточно самостоятельная и объёмная, чтобы не раздувать основную техническую спеку.

## Общее
* Потребуется минимальная очередь — делаем имитацию: синхронный драйвер по умолчанию, с возможностью переключиться на `database`-драйвер Laravel через `QUEUE_CONNECTION` в `.env`, без изменений в коде.
* На каждое валидное обращение отправляется **ровно одно** письмо, на два адреса — владельцу (`To`) и пользователю (`Cc`, буквальная реализация ТЗ "копия письма пользователю", см. `directives/summary-0.md`).
* Для локального тестирования используется вариант "отправки" писем через встроенный Laravel-транспорт `log` (`MAIL_MAILER=log` в `.env`) — реального SMTP нет, письмо не улетает, а рендерится и пишется в лог-файл. Настроен отдельный лог-канал под это (`MAIL_LOG_CHANNEL=mail` в `.env` → канал `mail` в `config/logging.php` → файл `storage/logs/mail.log`), чтобы не мешать письмам с общим логом приложения (`laravel.log`).

## Юниты
* **`App\Mail\NewFeedbackMail`** (Job + Mailable) — единственный класс письма-уведомления о новом обращении. Строится из уже провалидированной модели `Feedback`. `To`: `SITE_OWNER_EMAIL`, `Cc`: `$feedback->email`.
* **`FeedbackNotifier`** — тонкий координирующий сервис, вызываемый из `FeedbackService`, который ставит нужный Job в очередь, не заставляя `FeedbackService` знать детали отправки писем.

## Шаблонизация
* Движок — **Blade**, но **без HTML**: шаблоны рендерят чистый текст (никаких тегов разметки), просто используя синтаксис Blade (`{{ }}`, `@if` и т.п.) для подстановки данных.
* Расположение: `resources/views/mail/new-feedback/` — стандартное Laravel-место для mail-вью, сгруппировано в подпапку по имени письма.
* Файлов — два:
  * `resources/views/mail/new-feedback/subject.blade.php` — тема письма.
  * `resources/views/mail/new-feedback/body.blade.php` — тело письма.

## Содержание письма
* **Тема** (`subject.blade.php`): `Запрос #{{ $id }}` (про генерацию `id` — см. `ARCHITECTURE.md` §2.3, здесь не дублируется).
* **Тело** (`body.blade.php`):
  1. `Ваш запрос #{{ $id }} получен и принят в работу.`
  2. пустая строка
  3. `Сообщение:`
  4. пустая строка
  5. ровно `{{ $comment }}` — ровно как пришло после санитации, но в любом случае - через фильтры безопасного вывода
  6. `<подпись>` — статический текст, часть самого шаблона (не переменная, не `.env`; `MAIL_SIGNATURE` из `.env` больше не используется — см. `ARCHITECTURE.md` §5).

## Код
Реализовано: `App\Mail\NewFeedbackMail`, `App\Services\FeedbackNotifier`, шаблоны `resources/views/mail/new-feedback/{subject,body}.blade.php`, вызов из `FeedbackService` (после AI-анализа, см. `SPECS-AI.md`). Проверено юнит- и feature-тестами (`Mail::fake()`), реальная отправка не тестировалась (нет настроенного реального `MAIL_MAILER`/SMTP в этом окружении — только структура письма и адресация).
